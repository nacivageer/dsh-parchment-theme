# dsh-parchment-theme 决策记录

## 做什么

把 DeepSeek Harness Web GUI 的配色改成「旧纸 + 墨褐」，浅色叫羊皮纸、深色叫墨夜，正文默认京華老宋体。
目标形象参考：WPS 里一张做旧的稿纸、黑褐宋体字（2026-11-11 格给的截图）。

## 用什么栈

- 一个 DSH **bundle 插件**：Host 半是空 `apply()`，Client 半走 `window.__ModuleLoader__.load`。
- 主题手段是 `ctx.theme.overrideTokens(source, {token: {light, dark}})`，不是 `ctx.theme.register()`。
  - 理由：`register()` 的 `ThemeDefinition` 只能声明一个 `colorScheme`，且外观三选一（明/暗/跟随系统）是 ui-theme 里写死的 `CUBES`，第三方 id 进不去设置面板（`dsh-client-ui-theme` 源码 `AppearanceRow`）。覆盖层天然按当前 colorScheme 取值，跟随系统照常工作。
- token 取 `--dsw-alias-*` 全族 + 少量 design-platform.css 里写死的字面色（菜单 `#f8f9faf0`、阴影 `#0000000d` 等）。
- 字体通过 `--dsw-font-family` 令牌注入，写成 `var(--dsh-font-family-text, "京華老宋体"), …`，让设置里选的字体仍然优先。

## 怎么跑

```powershell
# 安装到当前 profile（desktop）
plugin_manager → install_bundle，target = 本目录绝对路径
# 之后刷新页面（client 模块不就地热更新）
```

停用：`plugin_manager → set_bundle / set_plugin（enabled: false）`，刷新即复原。

## 提交前

CI（`.github/workflows/test.yml`）只跑一条命令：`node test/smoke.mjs`，矩阵 ubuntu/windows × node 22/24。

- **push 前先本地跑 `npm test`（即 `node test/smoke.mjs`）。** 不跑的话失败要等 push 后几十秒才从 GitHub 通知回来，白等一轮，还得补一个 commit 洗红。
- **断言跟着实现在同一个 commit 里改。** 2026-11-11 `b343268` 把标题/正文字体家族对调，`test/smoke.mjs` 里「正文用寒蝉活宋体」的旧断言没动，run #10 当场红（`AssertionError: body text uses the sturdier Song face`）；14 秒后 `219e4d9` 补上断言才绿。拆成两个 commit 可以，但中间那个不能是红的——要么先改断言、要么一起提交。
- 动断言覆盖到的令牌（`--dsw-font-family`、zoom 规则、设置卡片描边等）之前，先 `Select-String test/smoke.mjs` 看有没有匹配它的 `assert.match` / `assert.equal`。

## 三个手段，别混用

1. **颜色** → `overrideTokens` 覆盖层（110 个 token）。
2. **字号/字体/层级** → 插件自有 `<style>`：`zoom` 整页缩放、`@font-face` + `unicode-range` 把京華限定在汉字、工作区行单独抬字号。
3. **正文字号阶梯** → `--dsh-content-font-size` 等三个变量（calc 阶梯的源头）。

踩过的坑：改 `--dsw-font-*` 那一族想让界面变大，结果只影响一半组件——侧栏根节点是字面量 `font-size:14px`，不读 token。一屏三种字号看着像叠字，是这么来的。

## 怎么查

- 覆盖层是否在：`cordis_inspect_query`（client / Theme / listTokens），动态 token 的 description 是 “Theme token registered by the current Client composition.”
- 层里单侧缺值时：浏览器 console 里 `[dsh-parchment-theme] tokens missing one palette: …`
- 字面色有没有漏：对照 `_tmp/tokens.md`（从 ui-theme 的 client.js 里抽出来的浅/深色 alias 全表），确认每个被改的用途都成对覆盖。

## 边界

- 不做纹理、不换图标、不改布局（2026-11-11 与格确认：先纯色看效果）。
- 不写 profile 的 `cordis.patch.yml` / `package.json`，全部交给 `plugin_manager`。

## 后来怎么变的（2026-11-12 更新）

上面「边界」里的前两条已被推翻，保留原文只为记录当时的决定：

- **加了纸纹**：两层 SVG `feTurbulence` 噪声（`body::after`），浅色 `overlay`、深色 `hard-light`。它会把所有表面提亮约 12 个色阶，所以表面色令牌都要按这个差反推，不能直接照抄取色。
- **换了图标**：新会话换羽毛笔、加载更早加沙漏（`assets/*.png` 走 CSS mask + `currentColor`），账号头像换火漆印 PNG。
- **改了布局密度**：侧栏根 17px、工作区行 18px、设置面板 `zoom:1.15`、会话正文阶梯 18px。整页 `zoom` 被永久放弃（会让弹层翻转判断错位），只留设置面板这一处。
- **语义强调色**：CSS 不能按文本选元素，Client 半层 `paintAccents()` 给「创造模式 / 完全权限 / 退出登录」打 `data-dsh-accent`，再由样式上色。
- 逐次改动的来龙去脉（含失败方案与实测数据）记在 `default-workspace/docs/tasks/parchment-theme.md`，版本级变化看 `CHANGELOG.md`。

## 页面排版档位（2026-11-12，v0.1.22）

主列那几个「普通页」（自动化任务、插件、插件市场）原先各背一套 12–15px 小字号。它们跟设置页对齐时的核心事实：**设置面板是唯一套了 `zoom:1.15` 的列**（`[class*="AnXs9G_panel"]`），所以「面板里写多少」和「主列该写多少」不是一回事。

| 视觉档 | 面板里写 | 主列写 |
|---|---|---|
| 页标题 | 18 / 26 / 600 | **21 / 30 / 600** |
| 栏目名 | 16 / 24 | **18 / 27** |
| 摘要 | 14 / 20 二级墨 | **16 / 22 二级墨** |

照抄面板数字会让主列那页小 13%，格一眼就看出来。判断某一页在不在面板里，看它注册进哪个槽（`main` vs 设置面板），不要从截图猜——插件页是 `main`（源码注释写明 "opens in the main column"），设置里的「插件市场」才是面板内那张。

定位钩子的优先级，从稳到脆：

1. 业务属性：`data-plugin-panel`、`data-plugin-header-part`、`data-plugin-group`、`data-chip`、`data-row-key`、`data-code-block-banner`。
2. 组件自带的语义类：`nUhMVa_panelHost`、`wtg9ga_moreMenu`（这类名字不带构建哈希）。
3. 构建哈希前缀：`olCj9W`（调度）、`V7pFBG`（插件管理）、`nUhMVa`（市场）、`wtg9ga`（侧栏）。升级必查。

同一个组件两处渲染时（dshmarket 在主列和设置面板各有一份），只给主列那份加档，用 `body:not(:has([class*="AnXs9G_panel"]))` 门控；反过来会把面板那份放大成 1.32 倍。

静态复现（`H:\DSH\home\.tmp-theme\`）两个必备件，缺一个就会得出错的结论：

- **基础令牌要手写**：`--dsw-radius-*`、`--dsw-elevation-soft` 是 ui-theme 用 JS 注入的，不在任何 CSS 文件里。只引 app CSS 的复现页里这些 `var()` 全部失效（圆角退回模块的 12px、阴影消失），看起来像"规则没命中"。
- **A/B 两列共享同一份纸纹**：不要用 iframe（iframe 里的纸色与外面不一致，会被误读成"改后变亮了"）；把新规则改成 `body #after …` 作用域，两列同页并排。

## 选择器陷阱（2026-11-13）

两处坑都出在「类名前缀」和「包裹层」上，代价是各多改一轮：

1. **属性子串匹配会扫到同前缀的所有变体**。市场任务行的类名是 `olCj9W_row`，同族还有 `olCj9W_rowTitle` / `rowSummary` / `rowContent` / `rowGlyph`。用 `[class*="olCj9W_row"]` 选行，等于把这五个元素全选中，于是内层元素也被塞了一条 `::after` 分隔线——一行下面出现两三条线。**要匹配「一个前缀类名本身」，必须用 `[class~=]`（按空格分词精确匹配）；`[class*=]` 只适合完整类名**（`olCj9W_rowTitle` 这种）。smoke 里已加 `assert.doesNotMatch` 守住这条。
2. **菜单触发按钮外面还有一层包裹**。primitives `Menu` 的 DOM 是 `容器 > _root_ > button`，`_root_` 带 `position:relative;display:inline-flex`。写 `容器 > button` 的直接子级选择器永远落空——「筛选」按钮连改两轮没动就是这个原因。定位这类触发器用 `button[aria-haspopup]`（语义钩子，不依赖哈希），或显式穿过包裹层（`> [class*="_root_"] >`）。

判据：**改完量到的值和改前一样，先怀疑选择器没命中，再怀疑被覆盖**。被覆盖通常留下「部分属性生效」的痕迹（字号变了、颜色没变）；完全没变，多半是根本没选到。

另一个相邻的坑：`::after` 想给「末行」去掉时，别在行自身上写 `:last-child`——任务行是 `<li>` 的唯一子元素，每条都满足 `:last-child`，结果所有线一起消失。按列表匹配：`listRows > :last-child .row::after`。

## 上游 tooltip 残留（2026-11-13）

DSH 的 `[role="tooltip"]` 偶发停在上次的位置不走：典型是侧栏「新会话 Ctrl+N」卡在标题栏左上角（压住「编辑」），以及消息上悬停「复制」时飘出的提示停在正文旁。**外观是主题的**（`--dsw-alias-tooltip-bg` 深棕胶囊 + 白字，深色下还加了 1px 浅边与阴影），**位置不归主题**：tooltip 的 left/top 由 primitives 组件写入，没写的时候就落在容器原点。

主题早期给「未定位的 tooltip」兜过底，后来移除了——修复属于上游组件，主题继续兜会和上游修复打架（`client.js` 里那段注释仍在）。所以现在只记录清掉干扰的操作，不改样式：

- **侧栏上的**（新会话 / 工作区等）：点左侧栏的收起图标把栏收起来，提示随侧栏卸载而消失，再展开即可。
- **消息区的**（复制、引号等）：切到另一个会话再切回来，旧提示随视图卸载而消失。
- 两者都只清当前那一次，下次悬停可能再出现；根治要等上游。

判断归属：样式与位置是两件事。深棕胶囊是主题给的；位置飘忽——同一套提示有时贴着按钮、有时卡在标题栏左上角——是定位写入时好时坏，归上游 primitives 组件。

## DSH 升级后的自检（2026-11-14 定）

**触发**：DSH 升级（例 `0.2.2-rc.2` → `0.2.2-rc.3`）后第一次开会话。只在这时做，不升级不做——本机停在哪个版本，就只对那个版本负责。

顺序是「便宜的先做」，哪一层挂了就停在那层修，别跳到界面上去猜。

1. **静态层**（不用开界面）
   - `node test/smoke.mjs`（= `npm test`）：期望末行 `smoke ok: <N> tokens, stylesheet <N> chars`。
   - 静态复现：`H:\DSH\home\.tmp-theme\` 下的脚本跑一轮——`quote\quote-harness.mjs`、`market\card-foot.mjs`、`market\measure.mjs`（通用 CDP 量值 + 截图）。它们直接吃真实 `client.js` 与真实模块 CSS，改前改后的差落在数值上，不靠眼睛。
   - 这一层红了就是 CSS / client.js 自己的问题，先修这里。
2. **令牌层**
   - `cordis_inspect_query`（client / Theme / listTokens）确认覆盖还在；界面 console 不应出现 `[dsh-parchment-theme] tokens missing one palette: …`。
   - 某个 token 从列表里消失 = 上游改名或删除，对应样式会**静默失效**；拿 `_tmp/tokens.md` 对照找新名。
3. **真机层**（只看，先不改）：刷新页面后依次扫侧栏、消息正文、代码块（衬底 + 1px 框线 + 标题斜体）、diff 行填充、HoverCard 卡面、插件市场三页、设置面板（`zoom:1.15` 那一列）、tooltip。三条判据：
   - 有白块从纸面里「挖」出来 → 某个表面 token 没覆盖到；
   - 容器把内容裁了 → 上游写死高度（判据 `scrollHeight > clientHeight`）；
   - HoverCard 底色回成写死的深灰 / `#2C2C2E` → `--dsw-alias-hovercard-bg` 那族又被绕开。
4. **真挂了怎么查**：先用 `::before{content:attr(class)}` 探针拿真实类名（被不透明子元素盖住时换个位置再探），再改选择器；优先业务属性钩子（`data-code-block-banner`、`data-changes-hover-preview`、`data-plugin-tab`、`hoverContent`、`historyHidden` 等），**别新增哈希选择器**——每升一次级它们就可能全落空。
5. **修完的判据**：静态层绿 + 真机三条判据都不中，才 bump 版本。

**不需要做的**：发新版**不用**去市场仓提 PR——`data/plugins/nacivageer__dsh-parchment-theme.yml` 没有 `version` 字段，版本与下载量由目录侧自动采集；想换市场截图就在本仓加/改 `screenshots.json`，也不用提 PR。只有要改**描述 / 分类 / 图标**时，才去 awesome-dsh-plugin 提一个只动自己那份 yml 的 PR。
